## 1. 工作流

```text
用户提出目标
  → Plan：拆解约束、给候选路线、用户拍板
  → Explore：读代码/报告/数据，先量后改
  → Implement：小步修改，保留旧行为默认
  → Test：C 仿真 / PC 单测 / 板上逐位
  → Review：读生成网表/报告，找“看起来正常但实际错”的地方
  → Fix：修正后重跑同一组验证
```

**分工原则**：

- 用户负责：目标、硬件操作、拍板取舍、板上动作（如贴手机/转头）；
- 模型负责：代码/脚本、测试、数据分析、文档、排错假设与验证命令；
- **任何模型结论都必须有可执行的验证**（C 仿真、单测、板上实测、报告回读），
  不能只靠“看起来对”。

**智能体用法**：

- 用后台任务跑 Vivado/HLS 长构建，前台继续写下一段代码；
- 用并行工具调用同时读多个文件/跑多组测试；
- 用 Explore/general-purpose 子代理做“只读盘点/大范围搜索”，结果只回结论；
- 用 cron/background 监控长任务，避免阻塞主线程。

## 2. 代表性协作片段

### 2.1 方向选择：三条路线

**用户**：说明比赛背景与已有材料，要求“精炼、完整、易读的 Plan，用于确定最终方向”。

**模型**：给出三条路线（DMS 全链路 / 精度深化 / 商用可信），
按“4 周可行性、已有资产利用率、评分抓手”对比，推荐 DMS 全链路 +
只补低光闭眼；并列出“明确不做”。用户随后拍板：
低光闭眼不做、显示走 PL OSD、object 用 margin 弃权。

**验证**：后续按该方向执行；W1 context 集成、W2 提交包装。

### 2.2 数据采集：pause/preannounce

**用户**：反馈采集时物体类开头混入上一段物体。

**模型**：先从 CSV/ROI 统计确认是“换段之后才换物体”，
不是标签脚本错；提出 `pause` 空档 + `--preannounce` 段尾提示，
并加 `trim=` 规则清洗已采数据。回放/重采后物体类开头干净。

**自我纠错**：最初只加 `--ctx-seg-settle`（段首静默），
实测 1.0 s 不够；改为显式 `pause` 段，问题才消失。

### 2.3 训练/定点：假 PASS

**用户**：要求按进度继续训练 context CNN。

**模型**：实现 dataset/model/train/export/eval；首次随机规格把激活压成 0，
4 个用例 logits 全相同、逐位比对照样 PASS。模型自己加了
“logits 不能全相同”的断言，并调整随机规格，避免假 PASS。

**验证**：C 仿真 4 用例逐层逐位；板上 20/20 随机输入与 numpy 金标准相同。

### 2.4 BD 集成：宽度断言误报

**用户**：继续做 BD 集成。

**模型**：写 `add_context_cnn.tcl`，扩 MI/SI、接 M07/S04、分配 0x41A00000；
第一次跑宽度校验时把 S03 期望写成 32、把 S01 查成 `rdata`，脚本中止。
读生成 `.hwh` 后发现：S01 是 S2MM 写通道（只有 `wdata`），S03 在 P2 后
已经是 64 位。修正断言后重跑，设计通过。

**教训**：**读生成物，不读记忆**；脚本的“失败”也可能是断言写错。

### 2.5 显示黑屏：`display_bisect`

**用户**：采集时屏幕没有显示。

**模型**：区分“CPU 写内存”和“MM2S 送显示”两个环节；
改 `display_bisect.py` 的第 4 种配置提示（应看到实时画面，不是纯白），
用户反馈 1/2/4 有画面、3 没有。据此定位：MM2S 在 DisplayCtrl 之前启动，
通道停在坏状态；改为 `disp_ctrl.start()` 后 reset+start MM2S。
之后采集 HUD 正常。

**自我纠错**：曾把“回读显示缓冲 == 写进去的帧”当成显示通路正常，
被满屏色块自检推翻。

### 2.6 Context 误判：native 检测尺度

**用户**：正常看也显示分心，右耳手机识别不到。

**模型**：先量 margin/ROI，排除阈值；发现 `--osd-native-haar` 下
`--face-detect-scale 2` 实际在 160×120 检脸，而训练/等价性测试是 320。
人脸框偏小/偏位 → context ROI 裁错。改为 native
`det_scale = args.face_detect_scale // d_native`（2→1）。
修正后右耳手机 margin 1027~1523，`phone_call` 触发；正脸不再误报。

**验证**：`context_log.csv` 记录 t=449.4~453.2 的 `phone_call`。

### 2.7 右耳手机：数据侧偏置

**用户**：右耳手机还是不行，怀疑数据训练。

**模型**：dump 显示 phone 被识别到，但 margin 在
500~1523 之间抖，夹杂 `unknown(809/913)`；旧 `obj_margin=1000`
会把候选 reset，2 s hold 永远攒不够。改成按类阈值
phone 500 / cigarette 1500 / other 1500，物体 release 1.2 s；
正常场景的 cigarette 假阳 948/956/1481 被 1500 挡住。
同一 ROI 水平翻转后 phone margin 掉到 772~943，说明**侧向数据偏置**
是根本问题；当前用阈值/hold 兜演示，彻底修法需补另一侧数据重训。

### 2.8 比赛要求：最终形态

**用户**：提供比赛 PDF，要求决定最终表现形式。

**模型**：提取权重（创新 30 / 性能 20 / 正确 20 / LLM+Skill 15 /
文档 15）与硬性提交项；对照现有工程，指出最大缺口是 `skill/`、
LLM 记录、英文目录/可复现文档；建议“DMS + 3 个通用 PYNQ Skill”，
停止加功能，优先包装。用户拍板后，模型生成提交包骨架、3 个 Skill、
设计报告与 LLM 记录。

## 3. 自我纠错轨迹（可核查）

| 错误结论/做法 | 实测证据 | 修正 |
|---|---|---|
| context 用 320×240 上采样图即可 | 正脸被判 left/right；margin 只有几十~几百 | 每 stride 读 640×480 全分辨率彩色→灰度 |
| native 的 `--face-detect-scale 2` 等价于 640 路 | 实际在 160×120 检脸，框偏小/偏位 | `det_scale // d_native`（2→1） |
| 扩 SmartConnect 后 S03 应为 32、S01 查 rdata | `.hwh` 显示 S03=64、S01 只有 wdata | 修正断言；读生成物 |
| 回读显示缓冲一致 = 显示通路正常 | 满屏色块仍全黑 | 加 `display_selftest`；MM2S 启动顺序修复 |
| 闭眼 prolonged 0.8 s 足够 | 正常段最长闭眼 1.13 s，误报 100 帧 | 改为 1.5 s |
| coverage 分母用 `min(窗口,运行时间)` | 正常段误报时 coverage=1.0 | 分母恒为 window_seconds |
| 物体头统一 margin 1000 | 右耳 phone 在 809/913 抖动被 reset | phone 500 / cigarette 1500 / other 1500 + release 1.2 s |
| 先写 C 模型再验 Haar 前 8 级 | 钉不死 cv2 归一化语义，候选集对不上 | 先做“单窗口 oracle”，语义未定不写 C |
| 把“级联命中率”当闭眼污染率 | 目视后高估约 3 倍 | 代理指标只作筛选，报数前目视 |
| `--train-all` 报告“误报 0%” | 监视集是训练集的子集（train/val 都含 hardneg） | 改整段会话留出 N3：**76/76 → 0/76** |
| 换权重只更新 HLS 源码 | 板上逐位测试 **20/20 FAIL**，像硬件坏了 | 三处同步：`hls/` + 板上金标准 + 板上副本 |
| `face lost` 只看 1.5 s 时间 | `face_stride=8` 下两次检测本身就隔 1.2 s，漏检一次就误判 | 时间超阈值 **且连续 ≥2 次检测无脸** |
| 活体挑战循环时 state≠verified 就降 STRANGER | 每隔几秒闪一次红，被当成“不灵敏” | `last_verified_id`：仅 verified 点亮，挑战期间保持 |
| `abs(yaw) < 80°` 就算可验证 | 本人转头 yaw −59.8° 被拍成陌生人 | `--face-id-stranger-max-yaw 45°` 弃权 |
| “包内脚本都能直接跑” | 8 个 ML 脚本找 `../PYNQ/src`、17 个 Tcl 写死绝对路径 | 双路径兜底 + 包内实测所有测试 |

## 4. 可复用的提示词/工作流（Skill 来源）

- “先量后改”：任何性能结论先给 A/B 实测/报告回读，再改代码；
- “读生成物”：BD 位宽/IP revision/ROM/bit-hwh 一律从生成文件读回；
- “失败要显式”：脚本在关键断言失败时退出，绝不“看起来成功”；
- “同一函数”：训练/部署裁剪、量化、解码必须共用单一真源；
- “默认不变”：新功能默认关，不传参数时与旧行为逐位相同；
- “数据标签双证据”：段意图 + 逐帧证据，缺一不可。

这些原则已落到 `skill/` 的三个技能包 README 中。
